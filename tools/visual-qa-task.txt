// Prompt executado pelo agendador (schtasks) a cada 30min via `devin -p`.
// Sessao autonoma: roda o ciclo visual-qa e aplica correcoes.

Execute a skill visual-qa neste projeto (club-penguin-browser).

Passos:
1. Verifique se o servidor do jogo responde. ATENCAO: o exec roda em WSL, onde `localhost` NAO enxerga o Windows — `curl localhost:3000` falha mesmo com o servidor no ar. Teste nesta ordem: `curl -m 3 http://localhost:3000/` e, se falhar, `curl -m 3 http://$(ip route show default | awk '{print $3}'):3000/`. Se ambos falharem, escreva uma linha em docs/visual-review-ERRO.md dizendo "servidor fora do ar" e encerre imediatamente — NAO tente subir os servidores.
2. Se estiver no ar, siga a skill visual-qa completa para a sala `town`:
   - Playwright MCP: abra http://localhost:3000/ e https://gopenguin.lol/?room=town em paginas separadas
   - Aguarde o jogo carregar (~10s) e capture screenshots em tools/shots/clone-town.png e tools/shots/ref-town.png
   - Rode: bash tools/gemini-vision.sh tools/visual-qa-prompt.txt tools/shots/clone-town.png tools/shots/ref-town.png > tools/shots/review-town-raw.txt
   - Leia tools/shots/review-town-raw.txt e salve o conteudo em docs/visual-review-town-<data de hoje>.md
3. Aplique no maximo as 3 correcoes visuais de maior prioridade que o Gemini apontar, alterando apenas client/src/. Seja conservador: nada de refatoracao, nada de mudanca de logica.
4. Rode `npm run build` dentro de client/ para verificar que nao quebrou nada. Se quebrar, reverta a ultima mudanca.
5. Encerre com um resumo de uma linha do que foi feito (ou "nada a corrigir").

Regras:
- Nao faca commit, nao faca push.
- Nao modifique arquivos fora de client/src/, docs/ e tools/shots/.
- Se alguma tool MCP nao estiver disponivel ou der erro, registre em docs/visual-review-ERRO.md e encerre — nao insista.
